# 隐私说明

Context Service Qoder 插件只在相应功能启用或用户主动调用工具时发送数据。

## 自动发送的数据

- 会话开始：发送会话标识，用于获取适用的规则、角色和会话状态
- 问题相关召回：启用后发送当前用户问题和会话标识，用于查询相关知识和长期记忆
- 对话同步：启用后发送当前轮的会话标识、用户文本和助手文本
- 长期记忆保存：启用后发送当前轮的会话标识、用户文本和助手文本，由服务判断是否形成长期记忆

正式一键安装时，会话开始上下文和问题相关召回默认开启，自动对话同步和长期记忆保存默认关闭。用户可以在安装时显式调整四项开关；已有配置重装时，未指定的开关保持原值。

## 不会自动发送的数据

插件不会把以下内容作为自动对话处理的一部分上传：

- 完整聊天记录
- 工具输入和工具输出
- 本地文件内容
- Git 历史
- 仓库名和工作目录
- 本地聊天记录文件路径

为了正确识别当前一轮对话，插件会在本机有限读取聊天记录末尾，但只发送当前轮所需的用户文本和助手文本。

## 工具调用

插件提供记忆、知识、规则、会话和事件工具。只有 Qoder 实际调用工具时，工具参数才会发送给 Context Service。部分工具会保存或删除记忆、追加事件；这些操作继续受 Qoder 权限确认控制。

## 本地保存的数据

插件在本机保存：

- 服务地址和 API Key
- 自动能力开关和超时设置
- 用于识别重复对话轮次的少量状态
- 正式安装所需的版本和安装状态

对话轮次状态不保存用户或助手正文。macOS/Linux 上的私密配置和状态使用仅当前用户可读写的权限。

默认卸载保留 API Key 配置和轮次状态。只有用户明确执行彻底清理时，才删除这些已知数据。

## 凭据安全

`/context-setup` 不从聊天中收集 API Key。请在本机终端使用隐藏输入完成配置。如果 API Key 被误贴到聊天、日志或其他共享位置，应立即撤销并轮换。

SaaS 运营方在向外部用户提供插件前，应公布数据保留、删除、驻留地域和子处理方政策。用户应确认这些政策符合自身的数据分级要求后，再开启问题相关召回、对话同步或长期记忆保存。
